## 1. 프로젝트 개요 (Project Overview)

### 1.1. 시스템 목적

본 시스템은 소비자(Client)가 모바일 앱 또는 PC에서 직관적인 3D 시뮬레이션을 통해 맞춤형 가구를 설계하고, 백엔드 엔지니어링 검증 서버와 다수의 지역 목수 장인(Craftsman, 匠人 [jiàngrén], 職人 [shokunin])이 보유한 '공방 표준 파라메트릭 모델' 및 '현장 필수 정보 역질문(RFI)' 워크플로우를 결합하여, **서버 추론 비용 제로(BYOK), 모바일-PC 100% 동일한 60 FPS 사용자 경험(Unified UX), 무결점 제조 데이터(STEP/DXF/BOM) 자동 생성**을 달성하는 통합 플랫폼이다.

### 1.2. 핵심 아키텍처 5대 원칙 (Architecture Principles)

| 번호 | 핵심 원칙명 | 핵심 전략 | 구현 기술 및 주요 역할 |
| :---: | :--- | :--- | :--- |
| **01** | **크로스플랫폼 단일 코어<br>(One Core, Adaptive Shell)** | 모바일과 PC 간 로직 분기 제거 | 모바일(Android/iOS WebView)과 데스크톱(Web/Tauri)이 단일 TypeScript + Three.js + JSCAD 엔진을 공유하여 100% 동일한 렌더링 및 조작감 제공 |
| **02** | **사용자 계정 기반 추론<br>(BYOK: Bring Your Own Key)** | 중앙 서버의 고비용 GPU 인프라 제거 | 무거운 LLM 추론은 사용자 단말기 Keystore에 보관된 개인 API Key(Gemini 등)로 모델 공급사에 직접 요청하여 서버 비용을 완전 제거 |
| **03** | **도메인 지식의 서버 격리<br>(Directive Synthesis)** | 지적 재산 보호 및 안정적 형상 생성 | 목재 공차 계산, 선반 처짐 검증, CAD 규칙 노하우는 백엔드 서버가 전담하여 실행 지침서(`.md`)와 어셈블리 트리 데이터로 합성해 클라이언트에 제공 |
| **04** | **양방향 인간 참여형 검증<br>(HITL & Multi-Bid)** | 백지 설계로 인한 하자 및 단가 상승 방지 | 장인의 필수 현장 정보 역질문(RFI)과 공방별 검증된 표준 템플릿 역제안을 통해 시공 불량률을 0%로 통제 |
| **05** | **하이브리드 CAD 코어 분기<br>(Dual CAD Engine)** | 60 FPS 실시간성과 밀링 정밀도 양립 | 실시간 기구학 조작은 경량 JSCAD + Three.js가 전담하고, 1:1 정밀 간섭 체크 및 STEP/DXF 추출 시에만 FreeCAD(Web Wasm 또는 로컬 MCP) 지연 구동 |

## 2. 사용자 역할 정의 (User Roles & Actors)

| 액터 (Actor) | 주요 사용 환경 | 핵심 권한 및 주요 수행 역할 |
| :--- | :--- | :--- |
| **소비자 (Client)** | 모바일 앱 (주)<br>PC 웹 브라우저 (부) | • 가구 외경 치수($W, H, D$) 및 부재 단수 입력<br>• 개인 LLM API Key 등록 및 로컬 암호화 보관<br>• 장인 RFI 질문 응답 (걸레받이 치수, 수납물 하중 등)<br>• 다수 공방 3D 제안 모델 스와이프 비교 및 3D Diff 검토<br>• 기구학 도어/서랍 개폐 모션 테스트, 최종 견적 승인 및 에스크로 결제 |
| **목수 장인 (Maker)** | PC / 태블릿 웹 포털 | • 공방 표준 파라메트릭 템플릿 등록 및 관리<br>• 소비자 설계 의뢰 실시간 검토 (3D X-Ray, 계절별 수축 시뮬레이션)<br>• 현장 필수 추가 정보 역질문(RFI) 체크리스트 발송<br>• 공차/결구 보정 및 동적 단가 산출을 통한 역제안 입찰<br>• 계약 잠금 시 1:1 제조 데이터(STEP/DXF/BOM) 일괄 다운로드 |
| **오케스트레이션 서버** | 클라우드 백엔드 인프라<br>(Python FastAPI) | • 수학적 공차, 선반 처짐비(Sagging), 힌지 회전 간섭 자동 계산<br>• 동적 마크다운 지침서(`cad_directive.md`) 및 어셈블리 트리 합성<br>• 공방 표준 모델 자동 피팅(Auto-Fitting) 및 적합도 점수 산출<br>• 기기 간 실시간 조작 상태 동기화 및 계약 SHA-256 해시 잠금 |

## 3. 상세 기능 요구사항 (Functional Requirements)

### 3.1. [FR-01] 크로스플랫폼 단일 UX 및 실시간 세션 동기화 모듈

| 요구사항 ID | 기능 명칭 | 상세 요구사항 명세 |
| :--- | :--- | :--- |
| **FR-01-01** | **어댑티브 레이아웃 전환** | 화면 너비와 입력 환경(터치/마우스)에 따라 동일한 뷰어 코어가 모바일에서는 '전체 화면 3D + 하단 바텀 시트', 데스크톱에서는 '좌-중-우 3분할 워크스페이스'로 반응형 자동 전환 |
| **FR-01-02** | **통합 포인터 입력 추상화** | 모바일의 멀티터치 제스처(1손가락 회전, 2손가락 줌/팬)와 PC 마우스 이벤트(좌클릭 회전, 휠 줌, 우클릭 팬)를 단일 입력 컨트롤러 인터페이스로 추상화하여 일관된 조작감 제공 |
| **FR-01-03** | **기기별 그래픽 품질 최적화** | 모바일 기기는 OOM과 발열을 방지하기 위해 픽셀 레이쇼를 최대 1.5로 제한하고 섀도우를 경량화하며, 데스크톱은 픽셀 레이쇼 2.0 이상 및 고품질 소프트 섀도우를 활성화 |
| **FR-01-04** | **실시간 기기 간 Seamless Handoff** | 스마트폰에서 조작하던 카메라 시점 좌표, X-Ray 상태, 도어 열림 각도, RFI 입력값이 Supabase Realtime을 통해 클라우드로 동기화되어 PC 접속 시 직전 상태를 그대로 이어받음 |

### 3.2. [FR-02] 클라이언트 BYOK 보안 관리 및 온디바이스 에이전트 연동 모듈

| 요구사항 ID | 기능 명칭 | 상세 요구사항 명세 |
| :--- | :--- | :--- |
| **FR-02-01** | **하드웨어 암호화 키 보관** | 사용자가 입력한 LLM API Key(Gemini 등)는 모바일의 Android Keystore(`EncryptedSharedPreferences`) 및 데스크톱 OS Keychain에 AES-256 암호화 저장되며 자사 서버로 일절 전송 금지 |
| **FR-02-02** | **키 유효성 즉시 검증 & 장애 대응** | 키 등록 시 최소 토큰 호출(Ping Test)로 정상 여부를 확인하고, 호출 중 HTTP 429(할당량 초과) 발생 시 지수 백오프(Exponential Backoff) 재시도 및 사용자 안내 팝업 노출 |
| **FR-02-03** | **지침서 주입형 클라이언트 직접 추론** | 서버로부터 수신한 엔지니어링 지침서(`.md`)를 시스템 프롬프트로 바인딩하고 로컬에 저장된 사용자 API Key를 결합하여 모델 공급사 클라우드에 직접 코드 생성 요청 |

### 3.3. [FR-03] 3D 파트 모델링 및 60 FPS 기구학 시뮬레이션 엔진

| 요구사항 ID | 기능 명칭 | 상세 요구사항 명세 |
| :--- | :--- | :--- |
| **FR-03-01** | **JSCAD 기반 파라메트릭 파트 생성** | 순수 함수 기반으로 측판, 상하판, 선반, 따내기 홈(Notch), 타공 홀(Hole) 등의 단일 부품을 CSG 불리언(합집합/차집합) 연산으로 1회 생성한 뒤 Three.js 버퍼 지오메트리로 변환 |
| **FR-03-02** | **계층형 피벗 씬 그래프 바인딩** | 어셈블리 트리의 고정 부재는 정적 메시로 배치하고, 가동 조인트는 회전축 좌표(`pivot_position`)에 빈 그룹 노드를 생성한 후 상대 좌표(`relative_position`)로 도어/서랍 메시를 바인딩 |
| **FR-03-03** | **60 FPS 기구학 모션 제어** | 슬라이더 조작 시 무거운 CSG 형상을 재계산하지 않고, 피벗 그룹 노드의 행렬(Z축 회전 각도, 서랍 인출 거리)만 GPU 레벨에서 갱신하여 저사양 모바일에서도 60 FPS 이상 보장 |
| **FR-03-04** | **X-Ray 결구 투시 및 분해도 뷰** | 판재 투명도를 35%로 전환하여 내부의 도미노 촉, 목심(Dowel) 등 결합 철물을 원색 강조하는 'X-Ray 모드'와, 조립 벡터 방향으로 부재를 펼쳐 보이는 '분해도(Exploded View)' 제공 |

### 3.4. [FR-04] 백엔드 엔지니어링 검증 및 지침서 합성 서버

| 요구사항 ID | 기능 명칭 | 상세 요구사항 명세 |
| :--- | :--- | :--- |
| **FR-04-01** | **수학적 구조 및 공차 자동 검증** | • 판재 두께를 제외한 내부 유효 치수의 조립 가능성 검증<br>• 선반 스팬 초과(예: 900mm) 시 처짐 경고 및 두께 상향(18T➔24T) 또는 수직 보강 규칙 트리거<br>• 도어 회전 반경($\sqrt{T^2 + G^2}$)을 계산하여 측판 간섭 방지 최소 클리어런스(1.5~2.5mm) 자동 감산 |

### 3.5. [FR-05] 장인 필수 정보 역질문(RFI) 및 사양서 자동 완성 워크플로우

| **FR-05-03** | **RFI 응답의 CAD 자동 컴파일** | 소비자 응답 제출 즉시 서버가 파라미터를 파싱하여 측판 걸레받이 따내기(Notch), 선반 두께 보강, 배판 원형 타공(Ø50mm)을 어셈블리 트리에 자동 반영하고 3D 뷰어 갱신 |

### 3.6. [FR-06] 다수 공방 표준 모델 자동 매칭 및 양방향 비교 입찰 모듈

| :--- | :--- | :--- |

| **FR-06-04** | **소비자용 3D Diff 비교 및 낙찰** | 소비자가 여러 공방의 제안을 스와이프하며 3D 형상, X-Ray 결구, 변경 내역(Diff 오버레이), 상세 견적(자재비/가공비)을 비교하고 최종 1개 공방을 낙찰 |

## 4. 전체 워크플로우 상태 머신 (System State Lifecycle)

| 단계 | 상태 코드 (State Code) | 명칭 (State Name) | 주관 액터 | 주요 실행 작업 및 전환 트리거 |
| :---: | :--- | :--- | :---: | :--- |
| **01** | `1_DRAFT_INIT` | 초기 설계 초안 | 소비자 | 기본 치수($W, H, D$) 입력 및 1차 3D 프리뷰 확인 후 견적 요청 발송 |
| **02** | `2_RFI_REQUESTED` | 현장 필수 정보 역질문 | 목수 장인 | 공방들이 의뢰 검토 후 걸레받이/하중/타공 관련 RFI 질문 카드를 발송한 상태 |
| **03** | `3_SPEC_COMPILED` | 사양서 컴파일 완료 | 오케스트레이션 서버 | 소비자 답변이 반영되어 따내기/보강이 적용된 완성형 사양서와 3D 트리 확정 |
| **04** | `4_MULTI_PROPOSAL_OPEN`| 다수 공방 제안 비교 | 소비자 & 장인 | 여러 공방의 표준 모델 적용안 및 수정 견적이 제출되어 소비자가 3D Diff 비교 중 |
| **05** | `5_CONTRACT_LOCKED` | 계약 체결 및 해시 동결 | 소비자 & 서버 | 소비자가 최종 공방을 낙찰하고 에스크로 결제 완료 시 SHA-256 해시 잠금 수행 |
| **06** | `6_PRODUCTION_RELEASED`| 제조 데이터 발행 및 생산 | 낙찰 장인 & MCP | FreeCAD MCP가 STEP, CNC DXF, 재단표(BOM)를 생성하여 공방 실가공 돌입 |

## 5. 비기능 요구사항 (Non-Functional Requirements)

| 품질 항목 | 요구 기준 지표 (Target Metric) | 세부 검증 기준 및 아키텍처 구현 방안 |
| :--- | :---: | :--- |
| **성능 (Performance)** | **60 FPS 이상**<br>모핑 딜레이 **0.2초 이내** | • 뷰포트 기구학 슬라이더 조작 시 60 FPS 이상 유지<br>• 공방 제안 탭 전환 시 3D 모델 모핑 지연 0.2초 이내 달성 |
| **안정성 (Stability)** | 상시 메모리 점유 **150MB 이하** | 모바일 WebView 환경에서 메모리 릭(Leak)을 철저히 차단하여 장시간 조작 시에도 OS에 의한 강제 종료(OOM Kill) 방지 |
| **보안성 (Security)** | **Zero-Knowledge BYOK**<br>일회용 서명 **JWT 적용** | • 사용자 개인 API Key는 클라이언트 단말 내부 Keystore에만 보관되며 패킷 전송 일체 금지<br>• 장인 검토 포털 접속 링크는 유효기간이 만료되는 일회용 JWT 서명 토큰으로 보호 |
